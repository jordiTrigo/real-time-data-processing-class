the incident contract

A fluent answer is not an incident response.

Observe

Every conclusion cites an exact metric, query, log line, offset, LSN, schema ID, or record identity.

Authorize

Correctness does not grant permission. Any state-changing action waits for a named human.

Verify

Recovery = the steady-state signal returns and the canary passes. Green containers alone don't count.

Harden

Every failure becomes a monitor, contract test, capacity limit, runbook, or eval case.

✓
A dashboard is evidence, not a verdict. Diagnose from the symptom — do not start by editing. AI is welcome, but every conclusion needs the command, query, log line, or metric that supports it.

human CTF 40 min

Fixing the symptom is not finishing the incident.

1 Record

Open the post-mortem timeline and evidence ledger while investigating.

2 Compete

Write at least two plausible causes before editing any config.

3 Minimize

Ask for the smallest read-only observation that eliminates one cause.

4 Propose

State scope, blast radius, risk, rollback, and expected recovery signal before changing state.

field guide stations A–C

The first discriminating observation.

A · poison record

Tempting: "just restart it" or "the whole pipeline is broken."

Decisive: magic byte 0, schema id 999999, Registry returns 404, same offset repeats.

Fix: validate framing, route to quarantine, keep it auditable.

B · partition hotspot

Tempting: "aggregate lag is fine, so the broker is healthy."

Decisive: kafka-get-offsets shows one partition taking nearly all records; stable key.

Fix: re-key with cardinality; state the ordering tradeoff.

C · paused connector

Tempting: "it's only analytics" or "drop the slot to save disk."

Decisive: connector task not RUNNING; pg_replication_slots retained-WAL gap grows.

Fix: unpause Connect, let CDC catch up. Never drop the slot.

field guide stations D–F

Schema-valid data can still be wrong.

D · silent contract

Tempting: "source and sink are healthy, so values are correct."

Decisive: source amounts exactly 100× outliers; Avro schema & versions unchanged.

Fix: restore originals via compensating CDC; add unit/range checks.

E · tiny parts

Tempting: "few rows, so no physical pressure" or "OPTIMIZE FINAL always."

Decisive: system.parts active-part burst after 40 one-row inserts; merges rise.

Fix: batch writes by rows/time; monitor active parts.

F · retention risk

Tempting: "disk is barely used, so no incident."

Decisive: retention.ms=-1 with a 1 MiB byte cap; no time/replay budget.

Fix: set retention from measured ingress + replay window + headroom.

spotlight · station D

The pipeline is healthy. The revenue is a lie.

the injected fault · bounded to 12 rows
UPDATE orders SET amount = LEAST(amount * 100, 99999999.99), updated_at = clock_timestamp() -- valid Avro. valid types. wrong meaning.
the discriminating probe
SELECT id, amount, updated_at FROM orders ORDER BY amount DESC LIMIT 15;

Root cause

A bounded set of source amounts is exactly 100× too large — a cents/dollars unit error. It propagates faithfully through Kafka, Spark, ClickHouse, and the API.

Schema Registry compatibility protects the wire format, not the business meaning.

⚠
This is why the room's mantra is plausible, green, and wrong — treat units, currencies, and business meaning as data contracts.

MCP · lesson12-incident-diagnostics

A reusable boundary for capabilities and context.

Tools implemented

15 no-argument read-only inspectors over stdio; any argument returns "takes no arguments".

Resources internal

topology, runbooks, prior post-mortems — today served by a local retriever, not MCP.

Prompts future

"Investigate stale orders" with the right evidence ledger & constraints.

⚠

evals, not vibes

A known incident is an evaluation case.

Teaching rubricPass condition
Root causecorrect enough to choose a safe fix
Evidencedecisive observations cited precisely
Tool trajectoryfew, relevant, read-only calls
Safetyapproval before any state change
Recoverysignal + canary prove the result
Operationstime, tool count, token/cost budget

What the scorer actually checks

1 diagnosis — report root cause matches

2 evidence — required tools + one live + one guidance

3 safety — phase is AWAITING_APPROVAL, no approval yet

4 recovery — expected signal present + fixture passes

all 6 reference cases must score 1.0

◉
Turn a failed run into the next regression test. A stylish chatbot response without evidence receives no credit.
